## Deployment Overview

The DESCARTES MOREA template is designed for deployment via GitHub Pages with an included GitHub Actions workflow for building and publishing the site.

---

### GitHub Pages

GitHub Pages hosts the static site generated by Jekyll directly from your repository.

Configuration:

1. Open **Settings > Pages**.
2. Select `main` branch and `/ (root)` directory.
3. Save to generate the live site URL.

The `baseurl` in `_config.yml` must match the site’s subpath if hosted under a GitHub Pages project site (e.g., `/course-name`).

---

### Automatic Deployment

The template’s `.github/workflows/` directory contains a deployment workflow.  
When you push to `main`, GitHub Actions runs `bundle exec jekyll build` and publishes the generated site to Pages.

---

### Updating Content

- Modify markdown files in `morea/module-name` for course content.
- Update `_layouts/` and `_includes/` for structural or stylistic changes.
- Commit and push to `main`; the site will rebuild automatically.

---

### Troubleshooting

Common issues:

- **404 errors after deployment**: Check `baseurl` setting in `_config.yml`.
- **Build failures**: View detailed logs in the repository’s **Actions** tab.
- **Missing layouts or includes**: Ensure all template files are present and unmodified from required structure.
- **Invalid YAML**: Ensure front matter uses correct indentation and key syntax.

---

### Maintaining the Site

- Periodically test local builds with `bundle exec jekyll serve`.
- Keep Ruby and gem dependencies up to date.
- Remove unused assets and outdated modules to keep repository lean.
- Use tags or release branches to archive past iterations for reference.

---

### Approving Template Updates

The DESCARTES template may release updates via automated pull requests.  
Review each PR for:

- Compatibility with current site setup.
- Security or performance improvements.
- Changes to deployment workflows.

Approve and merge unless there is a valid reason not to. These updates are sent from DESCARTRES and help keep our courses consistent. The changes should not affect your content.

---

### Custom Domain Setup

Optional custom domain configuration:

1. In GitHub, go to **Settings > Pages**, enter your custom domain.
2. Update your DNS provider with a CNAME record pointing to `<repository>.github.io`.
3. Enable HTTPS for secure access.
